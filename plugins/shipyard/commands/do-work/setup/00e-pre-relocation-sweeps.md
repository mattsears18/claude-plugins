### 0.45 Pre-relocation: session-state init + the worktree-cross-referencing sweeps ([#1202](https://github.com/mattsears18/shipyard/issues/1202))

**Run this BEFORE `EnterWorktree` ([step 0.5](00-config-worktree.md#05-move-into-the-orchestrators-worktree)) — while cwd is still the primary checkout and the harness's worktree-isolation guard has not yet activated for this session.** This step exists because two load-bearing rules were in direct conflict: step 0.5 mandates `EnterWorktree` as the primary relocation path (per [#844](https://github.com/mattsears18/shipyard/issues/844)) so a background-job session's `Edit`/`Write` calls aren't refused after isolating — but registering that isolation is exactly what **activates** the guard that then refuses every `git -C <other-worktree>` command an orphan-worktree sweep is built from (*"this command redirects git to the shared checkout via -C. Refusing it"*), plus the compound `for wt_dir in $(find ...)` reap loops those sweeps use (*"too complex to verify that it stays inside the worktree"*). So #844's fix for one background-job hazard silently disabled [#280](https://github.com/mattsears18/shipyard/issues/280)'s orphan-worktree reclamation — every orphan worktree from a crashed prior session accumulated forever, undetected, because the inspection step that must run *before* any reap (per [#838](https://github.com/mattsears18/shipyard/issues/838) — never reap without first checking for unpushed work) was itself refused. See [#1202](https://github.com/mattsears18/shipyard/issues/1202) for the repro.

**The fix is a pure reordering, not new machinery.** Every sweep below is unchanged in *what* it does; only *when* it runs moves earlier, to before the guard exists to trip over — this is Option 2 from [#1202](https://github.com/mattsears18/shipyard/issues/1202)'s suggested directions. Of the five sweeps that used to live in [00b's background bash group](00b-parallelization-cache.md#background-bash-group-fire-and-forget-from-step-07):

- **Three move here** — the orphan orchestrator-worktree sweep ([1.6.5](01-repo-recovery.md#165-reap-orphan-orchestrator-worktrees)), the stale agent-worktree reap ([3b](01c-label-recovery-refine.md#3b-reap-stale-agent-worktrees-from-dead-claude-code-sessions)), and the orphan `do-work/*` branch triage ([3c](01c-label-recovery-refine.md#3c-orphan-worktree-triage)) — because all three perform `git -C <other-worktree-path>` operations against worktrees other than the orchestrator's own.
- **Two stay put** — the orphan session-*file* sweep ([1.6](01-repo-recovery.md#16-reap-orphan-session-files-cost-ledger-recovery), pure `$SHIPYARD_HOME/sessions/*.json` housekeeping — no git worktree operations at all) and the label-create pass ([3a](01c-label-recovery-refine.md#3-ensure-label-exists--recover-from-prior-session)) — because they never touch a worktree path and the guard has no reason to fire on them. They remain in the post-relocation background group ([00b's step 0.7](00b-parallelization-cache.md#background-bash-group-fire-and-forget-from-step-07)), unchanged.

**None of the three moved sweeps NEEDS to run here to be reachable anymore — this position is now advisory continuity, not a load-bearing constraint ([#1355](https://github.com/mattsears18/shipyard/issues/1355), completed by [#1365](https://github.com/mattsears18/shipyard/issues/1365)).** [1.6.5](01-repo-recovery.md#165-reap-orphan-orchestrator-worktrees), [3b](01c-label-recovery-refine.md#3b-reap-stale-agent-worktrees-from-dead-claude-code-sessions), and [3c](01c-label-recovery-refine.md#3c-orphan-worktree-triage) now all route their entire discover-then-act logic through a single plain-command helper subcommand (`worktree-reap.sh reap-orphan-orchestrators` / `sweep-stale-agents` / `triage-orphan-branches`, respectively) instead of a `while`/process-substitution loop living directly in the orchestrator's own Bash tool call — the guard refuses a *loop shape in the caller's own command text*, not what an invoked script does internally, so a single subcommand call is reachable at any point in setup, pre- or post-relocation. [#1365](https://github.com/mattsears18/shipyard/issues/1365) ported 3c's own state machine (PR creation, auto-merge arming, the several tracked counters, and the issue #303 stale self-assign sweep) into `triage-orphan-branches`, closing the gap [#1355](https://github.com/mattsears18/shipyard/issues/1355) deliberately left open — 3c's discover-then-triage logic was substantially larger and more stateful than the other two, so porting it took its own follow-up issue rather than landing in the same PR. All three stay here for now (unchanged position, unchanged behavior) rather than moving purely for tidiness — see [`01d-orphan-orchestrator-worktree-reap.md`](01d-orphan-orchestrator-worktree-reap.md) and [`01c-label-recovery-refine.md`'s §3b](01c-label-recovery-refine.md#3b-reap-stale-agent-worktrees-from-dead-claude-code-sessions) / [§3c](01c-label-recovery-refine.md#3c-orphan-worktree-triage) for the per-sweep detail, including the caveat that the caller must still resolve `--repo-root` in its own, separate `Bash` call rather than in the same block as the sweep invocation (a data-flow-dependent refusal risk documented in [Claude Code's command-shape check](https://code.claude.com/docs/en/worktrees#how-claude-code-enforces-isolation), distinct from the loop-shape fix).

**Session-state must exist before the stale-worktree reap runs — the caveat #1202 flagged, worked through and confirmed load-bearing, not assumed away.** [Step 3b](01c-label-recovery-refine.md#3b-reap-stale-agent-worktrees-from-dead-claude-code-sessions)'s canonical implementation (`worktree-reap.sh reap-stale`) reads `.in_flight` off the session-state file via `session-state.sh read --path .in_flight` as a mandatory in-flight-membership guard (issue [#832](https://github.com/mattsears18/shipyard/issues/832)) — a worktree belonging to a worker this session just dispatched must never be misclassified `dead` and reaped. That read requires [step 1.5](01-repo-recovery.md#15-initialise-the-session-state-file)'s `session-state.sh init` to have already run, which in turn requires [step 1](01-repo-recovery.md#1-resolve-repo--user)'s repo/default-branch resolution and [step 1.3](01-repo-recovery.md#13-detect-the-silent-direct-merge-repo-shape-admin--ungated-merge-config) / [step 1.36](01-repo-recovery.md#136-detect-ci-executor-pool-capacity-and-clamp-toward-it-1141)'s `$EFFECTIVE_CONCURRENCY` clamp (`session-state.sh init --concurrency` needs a resolved value). So all four move here too, ahead of the sweeps that consume them. `reap_action` (the plain `reap` subcommand [1.6.5](01-repo-recovery.md#165-reap-orphan-orchestrator-worktrees) uses) does **not** read session-state at all — verified directly against `scripts/worktree-reap.sh` — so it has no ordering dependency of its own; it's grouped here purely because it shares the same cross-worktree-`git` constraint, not because it needs session-state too.

Run, in this exact order, all still resolving `CLAUDE_PLUGIN_ROOT` via the **pre-relocation** compound preamble ([00-config-worktree.md's step 0.3](00-config-worktree.md#03-claude_plugin_root-re-export-preamble-every-bash-tool-call)'s form — the post-relocation `.shipyard-plugin-root` stash doesn't exist yet at this point in the session) and `<session-id>` directly (no `.shipyard-session-id` stash needed either — that's a [step 0.55](00f-session-id-storage.md#055-session-id-storage-per-worktree-not-tmp) artifact written after relocation; the id itself is already known as the current Claude Code session identifier, independent of any file):

1. **[Step 1](01-repo-recovery.md#1-resolve-repo--user)** — resolve `<owner/repo>`, the `gh`-authenticated user, and `<default-branch>`. Cache all three. Unchanged commands; only the execution point moved.
2. **[Step 1.3](01-repo-recovery.md#13-detect-the-silent-direct-merge-repo-shape-admin--ungated-merge-config)** — the ungated-merge-shape detector + `$EFFECTIVE_CONCURRENCY` clamp. Unchanged commands; only the execution point moved.
3. **[Step 1.36](01-repo-recovery.md#136-detect-ci-executor-pool-capacity-and-clamp-toward-it-1141)** — the CI-runner-pool detector + second `$EFFECTIVE_CONCURRENCY` clamp. Unchanged commands; only the execution point moved.
4. **[Step 1.5](01-repo-recovery.md#15-initialise-the-session-state-file)** — `session-state.sh init` + the `.ci_capacity` write-through. Unchanged commands; only the execution point moved.
5. **[Step 1.6.5](01-repo-recovery.md#165-reap-orphan-orchestrator-worktrees)** — the orphan orchestrator-worktree sweep, via `worktree-reap.sh reap-orphan-orchestrators` ([#1355](https://github.com/mattsears18/shipyard/issues/1355)). Run it here **synchronously (foreground), not backgrounded** — the whole point of this reordering is to run before the guard exists, and a foreground call keeps that ordering trivially verifiable rather than depending on a background job's survival across the later `EnterWorktree` call (a live worktree-add followed immediately by a relocation into a NEW worktree is exactly the kind of interleaving worth not having to reason about).
6. **[Step 3b](01c-label-recovery-refine.md#3b-reap-stale-agent-worktrees-from-dead-claude-code-sessions)** — the stale agent-worktree reap, via `worktree-reap.sh sweep-stale-agents` ([#1355](https://github.com/mattsears18/shipyard/issues/1355)), with the `.in_flight` exclude-set safely readable per the ordering above (the helper reads it internally from the session-state file — issue #1147). Synchronous, same rationale.
7. **[Step 3c](01c-label-recovery-refine.md#3c-orphan-worktree-triage)** — the orphan `do-work/*` branch triage, via `worktree-reap.sh triage-orphan-branches` ([#1365](https://github.com/mattsears18/shipyard/issues/1365)). Synchronous, same rationale.

**Literal invocations for steps 5/6/7 ([#1455](https://github.com/mattsears18/shipyard/issues/1455)).** The three sweeps above do not share a flag vocabulary — deriving each call from prose alone costs one refused tool call per mismatch, every session. Below is the complete, copy-pasteable form for each, matching how [`classify-backlog.sh`](04-backlog-divert.md#4-fetch--rank-the-backlog) and [`next-available-version.sh`](../dispatch-rules.md#dispatch-rules-used-by-step-7-and-step-c) are documented elsewhere in this corpus. `worktree-reap.sh`'s own top-level `usage()` block (`-h`/`--help` on any subcommand) is the normative source if these drift — see [RATIONALE → 00e literal invocations](../../do-work-RATIONALE.md#00e-literal-invocations-issue-1455) for why the sub-file deep-links ([`01d-orphan-orchestrator-worktree-reap.md`](01d-orphan-orchestrator-worktree-reap.md), [`01c-label-recovery-refine.md`'s §3b](01c-label-recovery-refine.md#3b-reap-stale-agent-worktrees-from-dead-claude-code-sessions)/[§3c](01c-label-recovery-refine.md#3c-orphan-worktree-triage)) already carried this exact form and this step is the one that was missing it.

Resolve `<repo-root>` once, as its own plain `Bash` call, and reuse the literal path it returns for all three sweeps below (shell variables don't survive across separate `Bash` tool calls):

```bash
git rev-parse --show-toplevel
```

`<owner/repo>`, `<default-branch>`, and the session id are already known by this point — `<owner/repo>`/`<default-branch>` from [step 1](01-repo-recovery.md#1-resolve-repo--user) above, and `<session-id>` as the current Claude Code session identifier (no file lookup needed, per the note above this list).

**Step 5 — `reap-orphan-orchestrators`.** Requires `--repo-root` and `--session-id`; `--phase` is optional (defaults to `setup-1.6.5`, shown explicitly here for traceability):

```bash
export CLAUDE_PLUGIN_ROOT="${CLAUDE_PLUGIN_ROOT:-$(R=$(git rev-parse --show-toplevel 2>/dev/null); if [ -d "$R/plugins/shipyard/scripts" ]; then echo "$R/plugins/shipyard"; else I=$(jq -r '.plugins["shipyard@shipyard"][0].installPath // empty' "$HOME/.claude/plugins/installed_plugins.json" 2>/dev/null); if [ -n "$I" ] && [ -d "$I/scripts" ]; then echo "$I"; else echo "$R/plugins/shipyard"; fi; fi)}"
"$CLAUDE_PLUGIN_ROOT/scripts/worktree-reap.sh" reap-orphan-orchestrators \
  --repo-root <repo-root> --session-id "<session-id>" --phase "setup-1.6.5"
```

**Step 6 — `sweep-stale-agents`.** Requires `--repo-root` and `--session-id`; `--max-per-session`/`--warn-threshold` are optional and best-effort-default from `shipyard-config.sh` when omitted:

```bash
export CLAUDE_PLUGIN_ROOT="${CLAUDE_PLUGIN_ROOT:-$(R=$(git rev-parse --show-toplevel 2>/dev/null); if [ -d "$R/plugins/shipyard/scripts" ]; then echo "$R/plugins/shipyard"; else I=$(jq -r '.plugins["shipyard@shipyard"][0].installPath // empty' "$HOME/.claude/plugins/installed_plugins.json" 2>/dev/null); if [ -n "$I" ] && [ -d "$I/scripts" ]; then echo "$I"; else echo "$R/plugins/shipyard"; fi; fi)}"
"$CLAUDE_PLUGIN_ROOT/scripts/worktree-reap.sh" sweep-stale-agents \
  --repo-root <repo-root> --session-id "<session-id>"
```

**Step 7 — `triage-orphan-branches`.** Requires `--repo-root`, `--repo`, AND `--default-branch` — this is the one sweep with a different required-flag set from its two siblings above (it needs the default branch to diff each candidate worktree against, and `--repo` to open/query PRs — neither sibling sweep does either). `--session-id` is accepted-and-ignored here for CLI symmetry (issue #1400) but is NOT required — omit it or pass it, either is fine:

```bash
export CLAUDE_PLUGIN_ROOT="${CLAUDE_PLUGIN_ROOT:-$(R=$(git rev-parse --show-toplevel 2>/dev/null); if [ -d "$R/plugins/shipyard/scripts" ]; then echo "$R/plugins/shipyard"; else I=$(jq -r '.plugins["shipyard@shipyard"][0].installPath // empty' "$HOME/.claude/plugins/installed_plugins.json" 2>/dev/null); if [ -n "$I" ] && [ -d "$I/scripts" ]; then echo "$I"; else echo "$R/plugins/shipyard"; fi; fi)}"
"$CLAUDE_PLUGIN_ROOT/scripts/worktree-reap.sh" triage-orphan-branches \
  --repo-root <repo-root> --repo <owner/repo> --default-branch <default-branch>
```

Print each sweep's own output as documented at its linked step above (step 5's `summary: reaped=<R>`; step 6's `summary: reaped=<R> deferred=<D> unreaped=<U> remaining=<REMAIN>`; step 7's `failed-pr:`/`stale-assign:` lines plus its trailing `summary: salvaged=<S> abandoned=<A> stale_assigns=<SA>`).

**Steps 1.35 and 1.37 do NOT move.** Neither gates session-state init (both are independent advisory warnings with no downstream dependency), and neither performs a cross-worktree git operation, so both stay in their documented post-relocation position and run as part of the normal serial `01-repo-recovery.md` flow.

**What this step does NOT change.** [Step 1.7](01-repo-recovery.md#17-resolve-trusted-author-allowlist) (trusted-author allowlist) still runs post-relocation, unaffected — it has no worktree dependency. The post-relocation background group ([00b's step 0.7](00b-parallelization-cache.md#background-bash-group-fire-and-forget-from-step-07)) still fires, now carrying only 1.6 + 3a. `cleanup-summary.md`'s `wait $SETUP_BACKGROUND_PID` is unaffected — the background group still exists, just does less work than before.

**Failure mode if this step fails partway.** Same best-effort posture the sweeps always had — a failed or denied sweep here means the orphan-worktree backlog persists for a later session's setup to try again; it does not affect this session's own dispatch correctness (reclaiming *other* sessions' orphaned worktrees is unrelated to this orchestrator managing its own dispatched workers).
